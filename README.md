# KSPO 데이터 지도

> **KSPO 데이터 지도는 국민 누구나 궁금한 점을 문장으로 물어 국민체육진흥공단이 개방한 공공데이터를 찾고, 내려받기 전에 컬럼·샘플·이용 조건을 확인한 뒤 원문 포털로 바로 이동할 수 있게 만든 데이터 안내 서비스입니다.**
> 두 포털(공공데이터포털·문화빅데이터포털)에 나뉘어 개방된 공단 데이터 192건을 한 화면에 모았고, 회원가입·설치 없이 PC와 스마트폰 브라우저에서 바로 쓸 수 있습니다. 원하면 본인 키로 AI 추천을 켜 관련 데이터와 활용 조합도 안내받을 수 있습니다.

### 왜 만들었나요?

국민체육진흥공단의 데이터는 **공공데이터포털, 문화빅데이터포털(문화 빅데이터 플랫폼) 등 여러 곳에 나뉘어 공개**되어 있습니다.

그래서 연구자·학생·창업자·개발자처럼 데이터를 쓰려는 사람은

- 공단이 어떤 데이터를 개방했는지
- 어느 포털에 어떤 이름으로 있는지
- 내려받기 전에 어떤 항목이 들어 있고 어떤 조건으로 쓸 수 있는지
- 함께 쓰면 좋은 데이터는 무엇인지

를 사이트마다 따로 찾아봐야 했습니다. 데이터를 개방해도 찾고 이해하기 어려우면 활용으로 이어지기 어렵습니다.

**KSPO 데이터 지도는 누구나 이 과정을 한 화면에서 할 수 있도록 만든 공공데이터 안내 지도입니다.** (공단 내부 데이터 전체가 아니라, 두 포털에 개방된 데이터만 다룹니다.)

```mermaid
flowchart LR
    A[공공데이터포털] --> D[KSPO 데이터 지도]
    B[문화빅데이터포털] --> D
    D --> E[검색]
    D --> F[상세정보 확인]
    D --> G[관련 데이터 탐색]
    D --> H[원문 데이터로 이동]
```

## 이 화면에서 무엇을 할 수 있나요?

| 하고 싶은 일 | 데이터 지도에서 할 수 있는 것 |
|---|---|
| **공단이 어떤 데이터를 개방했는지 알고 싶다** | 데이터명·키워드로 통합 검색 |
| **데이터 이름을 몰라도 궁금한 점으로 찾고 싶다** | ‘질문 검색’에 문장으로 질문 → 이유와 함께 추천 (기본 검색은 AI 없이 누구나, 원하면 본인 키로 AI 추천) |
| **필요한 데이터만 골라보고 싶다** | 분야, 개방 포털, 제공형태(파일·API), 업데이트 주기로 필터 |
| **쓸 수 있는 데이터인지 판단하고 싶다** | 설명·컬럼 정의·샘플 행·포털 수정일·이용허락범위를 한 화면에서 확인 |
| **비슷한 데이터도 같이 보고 싶다** | 연관 데이터와 관계도(정보시스템·분야·데이터)로 연결 확인 |
| **실제 데이터를 받고 싶다** | 공공데이터포털·문화빅데이터포털 원문 페이지로 바로 이동 |

### 한마디로

**찾기 → 확인하기 → 관련 데이터 보기 → 실제 데이터 이용하기**까지 한 번에 이어집니다.

```mermaid
flowchart LR
    A[① 검색<br/>원하는 데이터 찾기] --> B[② 필터<br/>필요한 것만 좁히기]
    B --> C[③ 상세보기<br/>내용 확인]
    C --> D[④ 관계보기<br/>관련 데이터 확인]
    D --> E[⑤ 원문 이동<br/>파일·API 이용]
```

## 이용 사례: 체육시설 안전 서비스를 준비하는 창업자·연구자 - “체육시설 안전과 연계할 수 있는 데이터가 뭐 있어?”

| 단계 | 기존 방식 | KSPO 데이터 지도 |
|---|---|---|
| 찾기 | 어느 포털에 어떤 이름으로 있는지 몰라 공공데이터포털과 문화빅데이터포털에서 ‘체육시설’, ‘안전’, ‘안전점검’ 등 검색어를 바꿔 가며 각각 검색 | ‘질문 검색’에 문장 그대로 입력 → 기본 검색이 관련어(안전점검·체육시설안전·안전관리)까지 넓혀 8건을 일치 이유와 함께 추천 (AI 호출 없음) |
| 판단 | 후보마다 포털 상세 페이지를 열어 컬럼·이용조건을 따로 확인 | 상세 화면에서 컬럼 정의·샘플 행·이용허락범위·포털 수정일을 바로 비교, ‘연관 데이터’로 같은 출처 시스템 데이터까지 확인 |
| 더 보기 | - | (선택) AI 추천이 후보 데이터의 설명 요약·컬럼을 읽고 추천 이유와 함께 쓸 조합을 제안. 실패하면 기본 검색 결과로 전환 |
| 받기 | 다시 포털에서 해당 데이터를 찾아 이동 | ‘데이터 원문’ 버튼으로 해당 포털의 데이터 페이지로 이동 |

이 질문의 실제 기본 검색 결과(상위: 체육시설안전점검정보, 체육시설 안전점검 결함사진 학습 데이터, 전국체육시설 안전점검 정보 …)는 [docs/evidence](docs/evidence/2026-10-06-ai-compare.md) 의 비교 기록에 있습니다. 찾는 시간이 얼마나 줄어드는지는 측정하지 않았습니다(측정 절차는 [docs/EFFECT_MEASUREMENT.md](docs/EFFECT_MEASUREMENT.md)).

**같은 질문에 대한 실제 AI 추천 응답** (Gemini 3.5 Flash-Lite, 2026-10-06 [기록](docs/evidence/2026-10-06-ai-compare.md)에서 옮김)

> **AI 안내:** 체육시설 안전과 관련된 데이터로는 전국의 안전 점검 정보, 결함 사진 학습 데이터, 실태조사 등이 준비되어 있습니다. 체육시설 안전 점검 결과와 세부 시설 정보를 함께 활용하면 효과적으로 안전 관리 현황을 파악할 수 있습니다.
>
> 1. **전국체육시설 안전점검 정보** - 체육시설안전관리시스템(SFMS)을 기반으로 자율안전점검 및 안전점검 결과를 실시간 API로 제공합니다.
> 2. **체육시설안전점검정보** - 국민체육진흥공단에서 관리하는 전국 체육시설의 안전 점검에 대한 정보를 제공합니다.
>
> **함께 활용하면 좋은 조합 - 체육시설 안전점검 및 시설 현황 연계 분석:** 전국 체육시설의 기본 상세 정보와 실제 안전 점검 정보를 결합하여, 지역별 또는 업종별 취약 시설을 도출하고 안전 관리 대책을 수립하는 데 활용할 수 있습니다.

AI는 기본 검색이 고른 후보 데이터 안에서만 고르며(후보 밖 데이터는 화면에서 걸러냄), 추천 이유에 쓴 낱말이 그 데이터의 설명·항목에 실제로 있는지 기록에서 대조했습니다. 기본값은 키 없이 쓰는 기본 검색이고, AI 호출이 실패하면 기본 검색 결과를 그대로 보여 줍니다.

## 언제 쓰면 좋나요?

### 1. 연구·과제 자료를 찾을 때 (연구자·학생)
> “장애인 대상 체력 측정 데이터가 있을까?”

문장으로 물으면 관련 데이터를 이유와 함께 찾아 주고, 컬럼 정의·샘플 행으로 **연구에 쓸 수 있는지 내려받기 전에 확인**할 수 있습니다.

### 2. 서비스·창업 아이디어를 검토할 때 (창업자·개발자)
> “스포츠강좌이용권 이용 현황과 시설 위치를 함께 보고 싶어”

파일·API 제공 형태와 **이용허락범위**를 확인하고, 함께 쓰면 좋은 데이터와 다른 기관 데이터 활용 아이디어까지 살펴볼 수 있습니다.

### 3. 궁금한 현황·통계를 확인할 때 (시민·언론)
> “경륜 선수 성적을 분석하려면 어떤 데이터를 봐야 해?”

여러 사이트를 각각 검색하지 않고 **관련 데이터 후보를 한 화면에서 비교**한 뒤 원문 포털로 바로 이동합니다.

### 4. 체육단체·지자체가 사업을 준비할 때
> “신규 스포츠 사업 기획에 참고할 기금 지원 데이터는?”

공단이 개방한 기금 지원 데이터와 관련 데이터를 함께 찾아 **사업 준비의 근거 자료**로 활용할 수 있습니다.

```mermaid
flowchart TB
    A[연구자·학생] --> E[KSPO 데이터 지도]
    B[창업자·개발자] --> E
    C[시민·언론] --> E
    D[체육단체·지자체] --> E
    E --> F[찾는 시간 단축]
    E --> G[내려받기 전 내용 확인]
    E --> H[공공데이터 활용 확대]
```

## 사용 방법은 어렵지 않습니다

별도의 프로그램 설치나 회원가입 없이 PC와 스마트폰의 웹 브라우저에서 바로 사용할 수 있습니다.

### STEP 1. 데이터 지도에 접속합니다

👉 **https://pinkshark1.github.io/kspo_data_explorer/**

### STEP 2. 궁금한 점을 문장으로 묻거나 낱말로 검색합니다

첫 화면의 질문 칸이나 ‘질문 검색’ 메뉴에 문장으로 물으면 관련 데이터를 이유와 함께 추천합니다. 예:

- 장애인 대상 체력 측정 데이터가 있을까?
- 스포츠강좌이용권 이용 현황과 시설 위치를 함께 보고 싶어

낱말을 알면 위쪽 검색창에 바로 입력해도 됩니다. (예: 체력, 스포츠강좌, 체육시설, 체육진흥기금)

### STEP 3. 필요한 조건으로 범위를 좁힙니다

분야, 데이터 출처, 제공 형태, 업데이트 주기 등을 이용해 필요한 데이터만 확인합니다.

### STEP 4. 데이터 상세정보와 관련 데이터를 확인합니다

해당 데이터의 설명과 제공 정보를 보고, 연관된 데이터가 있다면 관계도에서 함께 살펴봅니다.

### STEP 5. 필요하면 원문 데이터로 이동합니다

실제 활용이 필요하면 연결된 공공데이터포털 또는 문화빅데이터포털로 이동해 원문 데이터를 확인합니다.

## 기존 방식과 무엇이 다른가요?

| 기존 | KSPO 데이터 지도 |
|---|---|
| 여러 사이트를 각각 방문 | **한 화면에서 먼저 통합 탐색** |
| 정확한 데이터명을 알아야 찾기 쉬움 | **키워드·분류로 탐색하거나 문장으로 질문** |
| 쓸 수 있는지 상세 페이지를 하나씩 열어 확인 | **컬럼·샘플·이용조건을 한 화면에서 비교** |
| 데이터 하나씩 개별 확인 | **관련 데이터를 함께 확인** |
| 어디서 원문을 받는지 다시 검색 | **원문 공개 사이트로 바로 이동** |

> **핵심은 데이터를 새로 만드는 것이 아니라, 공단이 이미 개방한 데이터를 국민 누구나 더 쉽게 발견하고 활용하도록 돕는 것입니다.**

## 기대 효과

아래는 측정하지 않은 **기대**입니다. 측정한 수치가 없어 숫자는 적지 않았습니다.

```mermaid
flowchart LR
    A[데이터 찾는 시간 ↓] --> B[데이터 이해 ↑]
    B --> C[국민의 데이터 활용 ↑]
    C --> D[공공데이터 가치 ↑]
```

- **데이터 접근성 향상** : 회원가입·설치 없이 누구나, 공단 데이터가 어디에 있는지 한 화면에서 파악
- **찾는 시간 단축** : 두 포털을 검색어를 바꿔 가며 반복 검색하는 시간 감소
- **데이터 이해 향상** : 내려받기 전에 컬럼·샘플·이용 조건으로 쓸 수 있는 데이터인지 판단
- **활용 확대** : 연구·창업·서비스 개발에 쓸 관련 데이터와 다른 기관 데이터 활용 아이디어 제공
- **다른 기관 확산** : 설정 파일만 바꿔 다른 공공기관도 자기 기관의 개방 데이터를 같은 방식으로 안내 ([대한체육회 적용 사례](examples/korea-sports-council/README.md))

# 운영자 참고

아래 내용은 일반 이용자가 아니라 **데이터 지도 운영·관리 담당자와 심사·검토자**를 위한 내용입니다.

## 내 PC에서 실행하기

Node.js 20 이상이 필요합니다. 화면 파일(`assets/`)이 이미 빌드되어 있어 실행만 할 때는 패키지 설치가 필요 없습니다.

```bash
git clone https://gitlab.aigov.go.kr/doongju1/kspo_data_explorer.git
cd kspo_data_explorer
npm start                     # http://localhost:4173 (종료: Ctrl+C)
```

- `index.html` 을 파일로 직접 열면(file://) 데이터를 읽지 못하므로 위처럼 웹서버로 엽니다.
- 소스(`src/`)를 고쳤다면 `npm install` → `npm run build` 로 화면 파일을 다시 만듭니다.
- 다른 데이터 폴더로 띄우기: `npm start -- --data examples/korea-sports-council/data` (대한체육회 공개데이터 이식 시험, [사례](examples/korea-sports-council/README.md))
- 점검(먼저 `npm install` - 화면 점검 도구가 들어 있음): `npm run check:data`(데이터) · `npm run check:ui`(화면, Chrome 또는 Edge 필요) · `npm run check:search`(질문 검색 품질) · `npm run check:ai`(AI 경로, 모의 서버) · `npm run evidence`(네 점검을 한 번에 실행해 [docs/evidence](docs/evidence/)에 기록)

## 주요 기능과 작동 방식

| 기능 | 작동 방식 |
|---|---|
| 데이터 탐색 | `data/explorer-data.json`(목록·컬럼·샘플)과 `data/portal-meta.json`(포털 수정일·이용허락범위)을 브라우저가 읽어 검색·필터·상세를 구성 |
| 관계도 | 데이터의 출처 시스템·분야로 묶은 연결을 캔버스에 그림 (노드 검색·확대·펼치기) |
| 질문 검색 - 기본 검색 | 질문에서 낱말을 뽑고 유의어 사전(`src/ai/thesaurus.js`)으로 넓혀 이름·키워드·컬럼·설명 일치를 점수화. AI 호출 없이 브라우저 안에서 처리 |
| 질문 검색 - AI 추천(선택) | 기본 검색 상위 후보(최대 30건, 검색이 약하면 전체 목록을 이름·분야만으로)의 이름·분야·설명 요약·컬럼을 이용자 본인 키로 Google Gemini API에 보내 추천 이유·관련도·활용 조합을 받음. 후보 밖 번호는 버리고, 실패하면 기본 검색 결과로 전환 |

### AI 추천 설정

- 모델: `data/site.json` 의 `ai.gemini.models` - Gemini 3.5 Flash-Lite(`gemini-3.5-flash-lite`, 기본), Gemma 4 31B(`gemma-4-31b-it`, 오픈 모델). 같은 키로 화면의 ‘모델’ 칸에서 고릅니다.
- 키: 화면의 ‘Gemini API 키’ 칸에 입력하며 이 페이지의 메모리에서만 쓰고 저장하지 않습니다. 소스·데이터·문서에 키를 넣지 않습니다.
- 교체: 같은 서비스의 다른 모델은 `ai.gemini.models` 에 추가, 다른 서비스는 `src/ai/providers/` 에 같은 형태의 파일을 추가합니다. 자세한 내용은 [docs/AI_FEATURE.md](docs/AI_FEATURE.md).
- 기관 AI 서버 연결 규격(운영하지 않음): 요청 `{ question, candidates }` → 응답 `{ summary, recommendations[{ no, relevance, reason }], combinations[{ title, nos, idea }] }`. 참조 구현은 `scripts/ai-gateway.mjs` 이며 `ai.modes` 에 `gateway` 를 켜고 서버 주소를 넣어야 동작합니다.
- 모델 선택 기준: 국민이 무료로 발급받는 키 하나로 쓸 수 있고, 같은 키로 오픈 모델(Gemma)까지 고를 수 있는 Gemini API를 택했습니다. 다른 서비스로 바꾸는 구조와 이력은 [docs/AI_FEATURE.md](docs/AI_FEATURE.md)에 있습니다.

## 서비스 운영 구조

개발·원본 관리는 **AI정부지원서비스 GitLab**, 공개 웹페이지는 **GitHub Pages**를 이용합니다.

```mermaid
flowchart TB
    A[AI정부지원서비스 GitLab<br/>원본 소스 관리] -->|main 반영| B[GitLab CI/CD]
    B --> C[Project Runner]
    C -->|자동 동기화| D[GitHub<br/>공개용 미러]
    D --> E[GitHub Pages<br/>데이터 지도 웹서비스]
```

| 구분 | 역할 |
|---|---|
| **GitLab** | 원본 소스 관리 및 수정 |
| **GitHub** | 외부 공개를 위한 미러 저장소 |
| **GitHub Pages** | 실제 데이터 지도 웹서비스 |

> **운영 원칙: GitLab = 원본 / GitHub = 공개용 미러 / GitHub Pages = 서비스 화면**

정상적인 운영 시 GitLab의 `main` 브랜치에 변경사항을 반영하면 CI/CD를 통해 GitHub로 동기화되고 웹페이지에 반영됩니다.

### 저장소 구성

```text
kspo_data_explorer/
├─ index.html          # 화면 진입점 (배포 대상)
├─ assets/             # 빌드된 화면 파일(app.js·app.css)·글꼴·오픈소스 고지 (배포 대상, npm run build 로 생성)
├─ data/               # 기관 설정(site.json)·데이터 목록(explorer-data.json)·포털 정보(portal-meta.json) (배포 대상)
├─ src/                # 화면 소스(React)와 질문 검색(src/ai)
├─ scripts/            # 로컬 서버·점검·포털 정보 수집·샘플 마스킹 스크립트
├─ docs/               # 데이터 구조, AI 기능, 다른 기관 적용, 효과 측정, 점검 기록(evidence)
├─ examples/           # 다른 기관 데이터 이식 시험 (화면은 이 폴더를 읽지 않음)
└─ .gitlab-ci.yml      # GitLab → GitHub 자동 동기화 설정
```
