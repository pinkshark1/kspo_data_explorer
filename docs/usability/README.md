# 소규모 사전 사용성 점검 진행 안내

KSPO 데이터 지도가 **기존 방식(공공데이터포털·문화빅데이터포털에서 직접 검색)** 보다 데이터를 빨리·정확하게 찾게 해 주는지, 직원 3~5명으로 작게 확인하는 절차입니다.
표본이 작아 통계적 결론을 내는 시험이 아니라 **사전 점검**입니다. 결과를 쓸 때도 이 이름(‘소규모 사전 사용성 점검’)과 참여자 수를 함께 밝힙니다.

## 준비물

- PC 1대, 크롬 또는 엣지, 초시계(또는 화면 녹화)
- 과제지 A·B (아래), 정답표(진행자만 봄)
- 기록 파일: [records-template.csv](records-template.csv) 를 `records.csv` 로 복사해 씁니다.
- 참여자는 이름 대신 `P1`~`P5` 로만 적습니다. (이름·소속은 기록하지 않음)

## 진행 순서 (1인당 약 30분)

1. **안내(2분)**: “두 가지 방법으로 데이터를 찾아 주세요. 빠르기보다 정확하게 찾는 것이 우선입니다.” 데이터 지도는 아래 ‘표준 소개’만 읽어 주고, 그 밖의 사용법은 알려 주지 않습니다.
2. **1차·2차 진행**: 아래 순서표대로 한 방식으로 과제 묶음 하나(3과제)를, 다른 방식으로 나머지 묶음을 합니다.
   - 같은 사람이 같은 과제를 두 번 하지 않도록 **과제 묶음 A·B를 나누고**, 방식·묶음의 순서를 참여자마다 바꿉니다(익숙해지는 효과를 줄이기 위해).
3. **시간 재기**: 과제를 읽어 준 뒤 ‘시작’에서 참여자가 ‘찾았다’고 말할 때까지. **과제당 최대 5분(300초)**, 넘기면 `300` 과 `N`(시간 초과)으로 적습니다.
4. **정답 확인**: 진행자가 정답표로 확인해 `Y`/`N` 을 적고, 막힌 곳·헤맨 곳을 메모합니다. 진행자는 도와주지 않습니다.
5. **기록 모으기**: 모든 참여자가 끝나면 `node scripts/summarize-usability.mjs` 로 요약을 만듭니다.

**데이터 지도 표준 소개 (그대로 읽기)**: “공단이 두 포털에 개방한 데이터를 한곳에서 찾는 화면입니다. 위쪽 검색창이나 ‘질문 검색’ 메뉴를 쓸 수 있고, 데이터를 누르면 상세 정보와 원문 포털 링크가 나옵니다.” (질문 검색은 **기본 검색**만 씁니다. AI 추천은 이 점검에서 쓰지 않습니다)

**기존 방식 시작 화면**: 공공데이터포털(https://www.data.go.kr)과 문화빅데이터포털(https://www.bigdata-culture.kr) 첫 화면을 탭 두 개로 열어 둡니다.

## 순서표

| 순서 | 1차 | 2차 | 해당 참여자 |
|---|---|---|---|
| 1 | 기존 방식 · 과제 A | 데이터 지도 · 과제 B | P1, P5 |
| 2 | 데이터 지도 · 과제 A | 기존 방식 · 과제 B | P2 |
| 3 | 기존 방식 · 과제 B | 데이터 지도 · 과제 A | P3 |
| 4 | 데이터 지도 · 과제 B | 기존 방식 · 과제 A | P4 |

## 과제지 (참여자에게 보여 줌)

두 묶음은 같은 유형(① 위치 찾기 ② 후보 찾기 ③ 컬럼 확인)을 다른 주제로 짝지었습니다.

**과제 A**

- **A1 위치 찾기**: ‘스포츠강좌이용권 이용현황 정보’ 데이터가 어느 포털에 개방되어 있는지 말하고, 그 데이터의 원문 페이지를 열어 주세요.
- **A2 후보 찾기**: 체육시설 안전점검 업무에 참고할 공단 공개데이터를 3건 이상 찾아 이름을 말해 주세요.
- **A3 컬럼 확인**: 경륜 선수정보 API(공공데이터포털)의 응답 항목 중 **선수 등급**을 나타내는 항목의 영문 이름을 찾아 주세요.

**과제 B**

- **B1 위치 찾기**: ‘체력측정 및 운동처방 종합 데이터’가 어느 포털에 개방되어 있는지 말하고, 그 데이터의 원문 페이지를 열어 주세요.
- **B2 후보 찾기**: 체육진흥기금 지원 실적을 볼 수 있는 공단 공개데이터를 3건 이상 찾아 이름을 말해 주세요.
- **B3 컬럼 확인**: 경정 선수정보 API(공공데이터포털)의 응답 항목 중 **평균 사고점수**를 나타내는 항목의 영문 이름을 찾아 주세요.

## 기록 방법

`records.csv` 에 과제 1건당 한 줄을 적습니다.

| 칸 | 값 |
|---|---|
| `participant` | P1~P5 |
| `order` | 순서표의 순서 번호 (1~4) |
| `method` | `portal`(기존 방식) 또는 `map`(데이터 지도) |
| `task` | A1~A3, B1~B3 |
| `seconds` | 걸린 시간(초, 정수). 시간 초과는 300 |
| `correct` | `Y` 또는 `N` |
| `note` | 막힌 곳, 정답 밖 답 등 (쉼표 대신 · 사용) |
| `date` | 점검일 (YYYY-MM-DD) |

## 요약 만들기

```bash
node scripts/summarize-usability.mjs                 # docs/usability/records.csv 를 읽어 docs/evidence/YYYY-MM-DD-usability.md 로 저장
node scripts/summarize-usability.mjs 다른파일.csv
```

요약에는 방식별 정답률, 소요 시간의 중앙값·최소·최대, 과제 유형별 중앙값, 참여자 수, 점검일, 화면 버전(커밋)이 들어갑니다. 평균 대신 중앙값을 쓰는 이유는 참여자가 적어 한 사람의 값에 크게 흔들리기 때문입니다.

## 결과를 쓸 때

- ‘소규모 사전 사용성 점검(참여자 N명, 과제 3개×2방식)’이라고 밝힙니다.
- 측정한 값만 씁니다. 예: “기존 방식 중앙값 ○초 → 데이터 지도 중앙값 ○초(참여자 4명)”. 비율(‘○% 단축’)을 쓰려면 같은 표의 중앙값으로 계산하고, 표본이 작다는 점을 함께 적습니다.
- 참여자가 공단 직원이고 진행자가 개발자라면 그 점도 적습니다(결과가 좋게 나올 수 있는 조건).
