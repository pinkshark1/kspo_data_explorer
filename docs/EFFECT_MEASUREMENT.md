# 효과 측정 방법 (소규모 사전 사용성 점검)

README 의 ‘기대 효과’는 아직 측정한 수치가 없는 **기대**입니다. 실제 수치는 아래 방법으로 직접 측정한 값만 기재합니다.

## 무엇을 재나

같은 직원이 **기존 방식(공공데이터포털·문화빅데이터포털에서 직접 검색)** 과 **KSPO 데이터 지도**로 데이터를 찾을 때의 **소요 시간과 정답 여부**를 비교합니다.

| 항목 | 내용 |
|---|---|
| 참여자 | 업무에서 공단 데이터를 찾아본 경험이 있는 직원 3~5명 (이름 대신 P1~P5) |
| 과제 | 3유형 × 2묶음: ① 위치 찾기(어느 포털·원문 페이지) ② 후보 찾기(업무에 쓸 데이터 3건 이상) ③ 컬럼 확인(API 응답 항목 이름) |
| 교차 배정 | 같은 과제를 두 번 하지 않도록 묶음 A·B를 나누고, 방식·묶음의 순서를 참여자마다 바꿈(4가지 순서) |
| 측정값 | 과제별 소요 시간(초, 최대 300초), 정답 여부(정답표 기준), 막힌 곳 메모 |
| 요약 | 참여자가 적어 평균 대신 중앙값·최소·최대, 정답률 |

진행 안내·과제지·정답표·순서표·기록 양식은 [usability/README.md](usability/README.md)에 있고, 기록은 `node scripts/summarize-usability.mjs` 가 요약해 `docs/evidence/YYYY-MM-DD-usability.md` 로 저장합니다.

## 현재 상태

- **측정하지 않았습니다.** 이번 공개본에는 절차·과제·정답표·요약 도구만 두며, 다른 기관이나 담당자가 같은 방법으로 잴 수 있습니다. 측정하면 그 값만 README 에 옮겨 적습니다.
- 자동으로 잴 수 있는 것은 따로 기록합니다: 화면·데이터·질문 검색 점검 결과는 [evidence/](evidence/) (`npm run evidence`), 다른 기관 데이터로 옮겼을 때의 처리 시간은 [examples/korea-sports-council](../examples/korea-sports-council/README.md).

## 보고할 때 지켜야 할 것

- 이름을 ‘소규모 사전 사용성 점검’으로 쓰고, 참여자 수·과제 수를 함께 밝힙니다.
- 측정하지 않은 수치(예: ‘탐색 시간 70% 단축’)는 쓰지 않습니다. 비율을 쓰려면 같은 요약표의 중앙값으로 계산하고 표본이 작다는 점을 적습니다.
- 측정일, 사용한 화면 버전(저장소 커밋), 데이터 기준일을 함께 적어 둡니다.
- 참여자가 공단 직원이고 진행자가 개발자라면 그 점도 적습니다.
