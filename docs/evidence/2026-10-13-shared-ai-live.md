# 공용 무료 AI 공개 화면 실제 호출 (2026-10-13)

공개 화면에서 API 키를 넣지 않고 ‘질문 검색 → AI 추천’을 실제로 호출해 확인한 기록입니다. 중계 서버(Cloudflare Worker) 실시간 로그(`wrangler tail`)에서 응답 상태와 처리 시간을 옮겼고, 화면 결과는 직접 보고 적었습니다. 질문 외의 요청 내용, API 키, 이용 확인 토큰은 기록하지 않았습니다.

| 항목 | 값 |
|---|---|
| 확인일 | 2026-10-13 (한국 시간) |
| 화면 | 공개 웹 화면 (GitLab `main` → GitHub Pages 배포본) |
| 호출 경로 | 브라우저 → 이용 확인(Cloudflare Turnstile) → 공용 중계(Cloudflare Workers 무료 플랜) → Google Gemini API |
| 모델 | Gemini 3.5 Flash-Lite (`gemini-3.5-flash-lite`, 공용 고정) |
| 이용자 키 | 없음 (키 입력란을 열지 않음) |
| 질문 | 동네 체육시설의 안전점검 결과와 위치를 함께 분석할 수 있는 공공데이터를 알려줘 |

## 1. 재시도 보완 전 (소스 커밋 ac9ec71)

| 시각 | 중계 응답 | 처리 시간 | 화면 |
|---|---|---|---|
| 18:24:27 | 502 | 0.38초 | ‘공용 무료 AI 서비스에 연결하지 못했거나…’ 안내 + 기본 검색 결과 8건 |
| 18:25:58 | 200 | 7.5초 | AI 안내 + AI가 고른 데이터 3건 |
| 18:26:31 | 200 | 12.2초 | AI 안내 + AI가 고른 데이터 4건 |
| 18:27:02 | 502 | 0.34초 | 위와 같은 실패 안내 + 기본 검색 결과 |
| 18:27:21 | 200 | 8.1초 | AI 안내 + AI가 고른 데이터 4건 |

18:27:02 실패는 무료 한도(429)가 아니었습니다. Google이 HTTP 503 `UNAVAILABLE`(“This model is currently experiencing high demand. Spikes in demand are usually temporary.”)로 곧바로 거절했습니다. 원인을 보려고 18:25부터 오류 종류와 문장만 잠시 로그에 남겼고, 확인한 뒤 그 코드를 지웠습니다. 18:24:27 실패는 이 로그를 넣기 전이라 원인이 기록되지 않았습니다. 다만 같은 질문에서 0.4초 안에 끝난 같은 형태의 실패였습니다.

## 2. 보완 (소스 커밋 ae6572c)

- 중계 서버가 Google의 500·503을 받으면 1초, 2.5초 뒤 같은 요청을 최대 2번 더 보냅니다. 이용 확인은 다시 하지 않습니다.
- 그래도 실패하면 HTTP 503 `{ error: "busy" }`를 돌려줍니다. 화면은 이를 한도 소진이 아닌 ‘혼잡’으로 안내하고 기본 검색 결과를 보여 줍니다. 한도 소진(429)은 다시 보내지 않습니다.
- 점검: `npm run check:shared-ai` 18/18, `npm run check:ai` 145/145 (모의 응답)

## 3. 보완 후 공개 화면 확인

| 시각 | 중계 응답 | 처리 시간 | 화면 |
|---|---|---|---|
| 18:36:10 | 200 | 1.7초 | 오류 안내 없음. AI 안내 + AI가 고른 데이터 4건 |

AI가 고른 데이터: 전국체육시설 안전점검 정보, 체육시설 안전점검 결함사진 학습 데이터, 체육시설안전점검정보, 전국공공체육시설 데이터. 모두 공단이 개방한 192건 안의 데이터입니다.

## 한계

- 보완 후 실제 503이 났다가 재시도로 회복되는 장면은 확인하지 못했습니다. 이 동작은 모의 응답 점검으로만 검증했습니다.
- 공용 무료 한도 소진(429)은 실제로 만들지 않고 모의 응답으로만 검증했습니다.
- 자동화 브라우저 중 화면 없는(headless) Chrome에서는 이용 확인이 통과하지 않았습니다. 일반 Chrome 창에서는 통과했습니다(같은 날, 추천 3건).
